# Как устроен бот

Документ для программиста, который пишет на C++ и для микроконтроллеров, но не писал ботов для Telegram и не работал с HTTP API. Сначала общая картина и понятия, потом путь одного сообщения через код, потом справочник по файлам и функциям.

## 1. Общая картина

```
 Телефон            серверы Telegram              ваш VDS (Docker)                 серверы Anthropic
┌────────┐        ┌──────────────────┐        ┌──────────────────────┐        ┌──────────────────┐
│Telegram│ ─────► │  Bot API         │ ◄───── │  бот (Python)        │ ─────► │  Claude API      │
│ клиент │ ◄───── │  api.telegram.org│ ─────► │  aiogram + anthropic │ ◄───── │  api.anthropic.com│
└────────┘        └──────────────────┘        │  SQLite: data/       │        └──────────────────┘
                                              └──────────────────────┘
```

Бот — обычная программа, которая сама ходит на два сервера по HTTPS:

- к **Telegram** — забрать новые сообщения и отправить ответы;
- к **Anthropic** — отправить диалог модели Claude и получить ответ.

Входящих соединений бот не принимает и портов не открывает. Поэтому ему не нужны ни публичный IP, ни домен, ни сертификат. Хватает любой машины с выходом в интернет, которая включена постоянно.

## 2. Понятия, без которых код не читается

### Telegram Bot API

- **Бот** в Telegram — это аккаунт, которым управляет программа, а не человек. Создаётся через служебного бота @BotFather, который выдаёт **токен** вида `123456789:AAH...`. Токен работает и как логин, и как пароль: кто его знает, тот управляет ботом.
- **Bot API** — HTTPS-интерфейс с JSON: `https://api.telegram.org/bot<токен>/<метод>`. Методы — `sendMessage`, `editMessageText`, `getFile` и т.д. Библиотека **aiogram** оборачивает их в Python-функции: `message.answer(...)` превращается в вызов `sendMessage`.
- **Update** — событие: новое сообщение, нажатие кнопки и т.п.
- **Long polling** — способ получать события. Бот вызывает `getUpdates`, и Telegram держит запрос открытым до ~10 секунд, пока не появится событие. Это как блокирующее чтение с таймаутом в цикле. Альтернатива — webhook: Telegram сам стучится к вам, но тогда нужен публичный HTTPS-адрес. Здесь используется long polling.
- **Одновременно может работать только один экземпляр бота с данным токеном.** Если запустить вторую копию (например, на ноутбуке и на сервере), Telegram начнёт отвечать второй ошибкой 409 Conflict.
- Ограничения, важные для кода: сообщение — не больше 4096 символов (Telegram считает их в UTF-16, эмодзи занимает два); бот может скачать файл не больше 20 МБ; слишком частые правки одного сообщения вызывают **flood control**: ошибку `RetryAfter` с числом секунд, которые нужно подождать.
- Длинный текст клиент Telegram сам режет на несколько сообщений, а альбом из нескольких фото приходит как отдельные сообщения с общим `media_group_id`. Бот склеивает такие пачки в один вопрос (см. раздел 4).

### Claude API

- **Messages API** — один HTTP-метод `POST /v1/messages`: на вход список сообщений диалога, на выход — ответ модели. Ключ API (`sk-ant-...`) идёт в заголовке. С сервером работает официальная библиотека `anthropic`.
- **API не хранит диалог.** Каждый запрос несёт всю историю целиком: все прошлые вопросы, ответы, картинки и PDF. Поэтому бот хранит историю у себя в SQLite и каждый раз отправляет её заново.
- **Токены** — единицы, на которые модель режет текст: примерно 3–4 символа английского текста или 2–3 символа русского. Картинка стоит до ~4800 токенов, страница PDF — от сотен до нескольких тысяч. Оплата идёт за токены: **входные** (всё, что отправили, включая историю) и **выходные** (что модель написала, включая её размышления). Цены указаны за миллион токенов.
- **Кэширование промпта.** Раз история при каждом запросе почти та же, API может запомнить её начало (префикс). Повторное чтение из кэша стоит в 10–40 раз дешевле обычного входа (зависит от модели), а запись в кэш — в 1.25 раза дороже. Кэш живёт 5 минут с последнего обращения. Любое изменение в начале запроса — другая модель, другой effort, правка старого сообщения — делает кэш бесполезным.
- **Размышления (thinking) и effort.** Перед ответом модель думает. Текст размышлений API не показывает (приходят пустые блоки с подписью), но токены за них оплачиваются как выходные и расходуются из лимита `max_tokens`. **Effort** (`low` … `max`) задаёт, сколько думать: больше — умнее, но дольше и дороже.
- **Стриминг.** Ответ приходит потоком событий (Server-Sent Events) по мере генерации — как байты из UART. Бот раз в 1.5 секунды переписывает сообщение в Telegram, и пользователь видит, как ответ «печатается».
- **Отказы и fallback.** У моделей есть классификаторы безопасности: иногда (в том числе по ошибке) модель отказывается отвечать, `stop_reason = "refusal"`. Для Opus 5.5, Sonnet 5.5 и Fable 5.1 бот включает **серверный fallback**: API сам повторяет запрос на резервной модели (например, Opus 4.8) в том же вызове. Платить нужно за обе попытки. После такого переключения API около часа сам направляет этот диалог на резервную модель. У Haiku 5.5 серверного fallback нет.
- **История только дописывается.** Блоки размышлений криптографически привязаны к точному тексту всего, что было до них. Если задним числом поправить старое сообщение, блоки станут недействительными (на новых аккаунтах это ошибка 400), а кэш сбросится. Поэтому бот никогда не редактирует историю: только добавляет. Это важное архитектурное ограничение, и из него следуют некоторые решения ниже, например уменьшение картинок сразу при получении.

### asyncio — если привыкли к потокам и OpenMP

Бот однопоточный. Python-библиотека `asyncio` — это кооперативная многозадачность: один цикл событий (event loop) и много сопрограмм. Похоже на суперцикл в прошивке, где каждая задача — конечный автомат, только автомат за вас строит компилятор.

- `async def f()` объявляет сопрограмму, `await x` — точку, где она может уступить процессор, пока ждёт сеть или таймер.
- Между двумя `await` код выполняется атомарно, никто его не прервёт. Поэтому общие структуры `busy` и `pending` в `main.py` не нуждаются в мьютексах: проверка «есть ли пользователь в `busy`» и добавление в `busy` идут без `await` между ними.
- aiogram запускает обработку каждого события отдельной задачей. Пока один пользователь ждёт ответа Claude (это десятки секунд сетевого ожидания), бот обслуживает остальных.
- Тяжёлую работу процессора — сжатие картинок через Pillow — бот отправляет в отдельный поток (`asyncio.to_thread`), чтобы она не останавливала цикл событий. Запросы к SQLite короткие и выполняются прямо в цикле.

## 3. Где что лежит

```
bot/
  config.py   настройки из .env, список моделей, цены и расчёт стоимости
  storage.py  SQLite: пользователи, доступ, диалоги, расход
  content.py  сообщения Telegram → блоки для Claude API (текст, фото, PDF, файлы)
  claude.py   запрос к Claude API: стриминг, fallback, подготовка истории, тексты ошибок
  main.py     всё, что касается Telegram: команды, кнопки, сбор сообщений, отправка ответа
tests/        автотесты: настоящие aiogram и anthropic, подменена только сеть
Dockerfile, docker-compose.yml   как собрать и запустить контейнер
.env.example  образец файла настроек (сам .env с секретами в git не попадает)
```

## 4. Путь одного сообщения

Пусть пользователь присылает альбом из двух фото с подписью «Что общего?».

1. **Приём.** aiogram получает три события `getUpdates` (два фото, подпись — у первого) и для каждого запускает `on_message` (`main.py`).
2. **Доступ.** `allowed()` проверяет Telegram ID по `ALLOWED_USER_IDS`, `ADMIN_USER_IDS` и таблице `allowed` (её пополняет команда `/allow`). Чужому бот отвечает «доступа нет» и показывает его ID.
3. **Сбор пачки.** Первое сообщение создаёт `pending[uid] = [сообщение]` и ждёт, пока новые сообщения перестанут приходить (по секунде, до 10 раз). Остальные части альбома просто дописываются в `pending[uid]`. Если в это время уже идёт генерация ответа (`uid in busy`), новое сообщение получает честный ответ «не отправлено».
4. **Лимит расходов.** `over_monthly_limit()` — если в `.env` задан `USER_MONTHLY_LIMIT_USD`, а пользователь (не админ) уже потратил столько в этом месяце, запрос не отправляется.
5. **Содержимое.** `batch_content()` (`content.py`) скачивает файлы из Telegram и превращает каждое сообщение в блоки API: `image` (base64), `document` (PDF в base64) или `text`. Картинки проходят через `prepare_image()`: формат определяется по содержимому, большие уменьшаются до 2000 px и сжимаются. Файлы и картинки ставятся перед текстом.
6. **История и проверка размера.** Из SQLite берётся вся история текущего диалога, к ней добавляется новый ход. `payload_bytes()` оценивает размер запроса. Если он больше ~30 МБ (лимит API — 32 МБ), бот не отправляет заведомо обречённый запрос, а советует начать новый диалог.
7. **Запрос.** `ClaudeClient.ask()` (`claude.py`) открывает стрим с моделью и effort пользователя, включённым кэшем и fallback. Каждый фрагмент текста вызывает `on_text()`, а та раз в 1.5 секунды правит сообщение «⏳ Claude думает…» (`safe_edit()`).
8. **Учёт.** `record_usage()` пишет в таблицу `usage` по строке на каждую попытку модели (при fallback их две) со стоимостью из `config.cost_usd()`.
9. **Разбор исхода.** Если модель отказала, не уложилась в контекст или ничего не сказала (весь лимит ушёл на размышления), бот объясняет это и **не сохраняет** ход, чтобы не засорять историю. Иначе вопрос и ответ дописываются в историю.
10. **Отправка.** `send_final()` переводит Markdown от Claude в HTML Telegram (`telegram_format`), режет на куски до 4096 символов и отправляет. Если Telegram не принял HTML какого-то куска, этот кусок уходит обычным текстом. Под ответом могут быть пометки: «ответ обрезан», «ответила резервная модель», «диалог уже большой — начните новый».

## 5. Справочник по файлам и функциям

### `bot/config.py` — настройки и цены

| Что | Зачем |
|---|---|
| `MODELS` | Модели для кнопок: ID в API → подпись. |
| `EFFORTS` | Уровни effort для кнопок. |
| `MODELS_WITH_FALLBACK` | Модели, для которых включается серверный fallback (у Haiku 5.5 его нет). |
| `PRICES`, `CACHE_WRITE_MULTIPLIER`, `LONG_PROMPT_PRICES` | Цены за 1M токенов: вход, выход, чтение кэша. Запись в кэш стоит 1.25 × входа. У Haiku 5.5 промпт длиннее 100K тарифицируется по второй, в 5 раз более дорогой, сетке. Есть цены и для резервных моделей fallback. |
| `_price_key(model)` | Находит модель в `PRICES` по самому длинному префиксу, чтобы `claude-opus-5-5` не перепутать с `claude-opus-5`. |
| `cost_usd(...)` | Стоимость одного обращения в долларах; `None`, если цена модели неизвестна. |
| `_ids`, `_int`, `_float` | Читают переменные окружения и при ошибке останавливают бот с понятным сообщением. |
| `Config` | Неизменяемая структура со всеми настройками. |
| `load()` | Читает `.env` (через окружение) и проверяет значения. |

### `bot/storage.py` — база SQLite

Таблицы: `users` (модель, effort и текущий диалог пользователя), `allowed` (кому выдан доступ через `/allow`), `conversations` (диалоги и их системный промпт), `messages` (история в виде JSON — ровно то, что уходит в API), `usage` (токены и стоимость каждого обращения).

| Метод | Что делает |
|---|---|
| `__init__` | Открывает базу и создаёт таблицы. Если нет прав на папку, останавливается с подсказкой. |
| `_migrate` | Обновляет базу от прежней версии: добавляет колонку стоимости и пересчитывает её. |
| `is_allowed_extra`, `allow`, `deny`, `allowed_list` | Доступ, выданный командами `/allow` и `/deny`. |
| `get_settings` | Настройки пользователя; при первом обращении создаёт запись со значениями по умолчанию. |
| `set_model`, `set_effort` | Сохраняют выбор кнопками. |
| `new_conversation` | Начинает новый диалог и делает его текущим. |
| `conversation`, `history`, `append`, `message_count` | Чтение и дописывание истории (только добавление). |
| `purge_old_conversations` | Удаляет историю брошенных диалогов, где последнее сообщение старше заданного срока. Текущие диалоги не трогает. |
| `add_usage`, `usage_since`, `spent_since` | Учёт расхода: запись, сводка для `/usage`, сумма для месячного лимита. |

### `bot/content.py` — что прислал пользователь

| Что | Зачем |
|---|---|
| `MAX_DOWNLOAD_BYTES` (20 МБ) | Больше Telegram ботам не отдаёт. |
| `MAX_TEXT_FILE_BYTES` (300 КБ) | Текстовый файл целиком попадает в историю и оплачивается заново с каждым сообщением, поэтому большие логи отклоняются. Пользователь получает объяснение. |
| `MAX_IMAGE_SIDE` (2000 px) | Если в запросе больше 20 картинок (считая картинки из прошлых ходов), API требует, чтобы каждая была не больше 2000 px. Историю менять нельзя, поэтому картинки уменьшаются сразу. Модель всё равно видит максимум 2576 px. |
| `MAX_IMAGE_B64_BYTES` (5 МБ) | API принимает картинку до 10 МБ в base64; бот держит запас, чтобы весь запрос оставался меньше 32 МБ. |
| `UserError` | Исключение с текстом, который можно показать пользователю. |
| `prepare_image(data)` | Определяет формат по содержимому, а не по имени файла. Подходящую картинку отдаёт как есть, остальные уменьшает и перекодирует в JPEG: учитывает поворот из EXIF, заливает прозрачность белым, снижает качество, пока не уложится в лимит. |
| `_document(bot, doc)` | PDF (с проверкой сигнатуры `%PDF-`), картинка файлом, текстовый файл (UTF-8 или cp1251). Всё остальное отклоняется. |
| `message_blocks(message, bot)` | Блоки одного сообщения: медиа, затем подпись. |
| `batch_content(messages, bot)` | Блоки нескольких сообщений одной пачки: сначала файлы и картинки, потом текст. |

### `bot/claude.py` — разговор с Claude API

| Что | Зачем |
|---|---|
| `FALLBACK_BETA`, `BINDING_BETA` | Включаемые бета-функции API: серверный fallback и мягкая обработка несовпадения истории (блоки размышлений, которые нельзя использовать, отбрасываются, а не вызывают ошибку 400). |
| `Attempt` | Одна попытка модели: какая модель и сколько токенов. |
| `Reply` | Итог запроса: текст, что сохранить в историю, причина остановки, попытки, кто ответил, был ли fallback. |
| `_history_content(blocks)` | Готовит ответ модели к сохранению. Выбрасывает маркеры fallback и блоки размышлений до точки переключения модели, выбрасывает пустые текстовые блоки (API их не принимает). Возвращает `[]`, если модель не сказала ни слова. |
| `_attempts(usage, ...)` | Расход по попыткам из `usage.iterations`. Верхнеуровневый `usage` описывает только попытку, давшую ответ, а отклонённая попытка тоже оплачивается. |
| `ClaudeClient.ask(...)` | Стримит ответ. Параметры запроса: `thinking: adaptive`, `output_config.effort`, `cache_control` (кэш), `fallbacks: "default"`, `max_tokens` из настроек. Обрыв связи посреди ответа превращает в ошибку SDK `APIConnectionError`. |
| `error_text(e, model)` | Переводит ошибку API в понятный текст: перегрузка (включая ошибку посреди стрима, у которой HTTP-статус 200), слишком большой запрос, кончились деньги, сработал лимит расходов, модель недоступна, неверный ключ и т.д. |

## 6. Деньги

Стоимость одного ответа примерно такая:

```
вход × цена_входа + чтение_кэша × цена_чтения + запись_в_кэш × 1.25 × цена_входа + выход × цена_выхода
```

Цены за 1M токенов на октябрь 2026 (вход / выход / чтение кэша):

| Модель | Вход | Выход | Чтение кэша |
|---|---|---|---|
| Opus 5.5 | $4 | $20 | $0.20 |
| Sonnet 5.5 | $2 | $10 | $0.20 |
| Haiku 5.5 | $0.10 ($0.50, если промпт > 100K) | $0.50 ($2.50) | $0.01 ($0.05) |
| Fable 5.1 | $10 | $50 | $0.25 |

Что из этого следует:

- **Длинный диалог дорожает с каждым сообщением**, потому что вся история отправляется заново. Кэш сильно смягчает это, пока сообщения идут чаще, чем раз в 5 минут. После паузы история записывается в кэш заново по 1.25 × цены входа. Для диалога на 300 тыс. токенов на Fable 5.1 это около $3.75 за одно сообщение после перерыва. Когда тема сменилась, начинайте новый диалог: `/new`.
- **Смена модели или effort посреди диалога** тоже заново оплачивает всю историю по полной цене. Бот об этом предупреждает.
- **PDF и картинки дорогие:** каждая страница PDF обрабатывается и как текст, и как изображение. Большой PDF быстро делает диалог тяжёлым; бот один раз предупредит, когда диалог перевалит за 150 тыс. токенов (за 100 тыс. — для Haiku).
- **Высокий effort** означает больше токенов размышлений, а они оплачиваются как выход.

**Насколько корректно сравнивать модели по этой таблице.** Сравнение по цене за токен даёт только грубую оценку стоимости ответа по трём причинам. Первая: одинаковый текст разбивается на разное число токенов у моделей с разными токенизаторами. Например, у Haiku 5.5 на ~30 % больше токенов, чем у Haiku 4.5. Вторая: одинаковое название effort у разных моделей означает разный объём размышлений. По документации Anthropic, Opus 5.5 на `medium` в их тестах превосходил Opus 5 на `high`. Третья: разные модели решают одну задачу разным числом токенов. Надёжно сравнить можно только на своих вопросах, глядя на `/usage` и на Anthropic Console.

**`/usage` — оценка, а не счёт.** Бот считает по ценам из `config.py` и по токенам, которые вернул API. Он не знает о налогах и изменении цен. Он не учитывает обрывы: если стрим прервался ошибкой, токены уже сгенерированной части могли быть списаны, но в учёт бота не попали. Точная сумма — в Anthropic Console → Usage / Billing.

**Ограничители расходов** (от жёсткого к мягкому):

1. **Spend limit в Anthropic Console** (Settings → Billing → Spend limits). Это жёсткий месячный потолок на всю организацию: когда он достигнут, API начинает отвечать ошибкой, и бот сообщит об этом. Обязательно поставьте его.
2. **Предоплата.** API работает на заранее купленных кредитах. Если не включать автопополнение (auto-reload), больше, чем положили, потратить нельзя.
3. **`USER_MONTHLY_LIMIT_USD` в `.env`** — месячный лимит бота на каждого пользователя, кроме админов. Проверяется перед запросом, поэтому один запрос может немного перешагнуть лимит.

## 7. Защитные проверки и лимиты

| Ограничение | Откуда | Что делает бот |
|---|---|---|
| Файл больше 20 МБ | Telegram не даёт боту скачать | Сразу объясняет. |
| Текстовый файл больше 300 КБ | Решение бота: дорого пересылать каждый раз | Просит прислать фрагмент. |
| Картинка больше 2000 px или 5 МБ в base64 | Лимиты API (картинки больше 2000 px запрещены, если в запросе больше 20 картинок; размер — до 10 МБ) | Уменьшает и сжимает. |
| Запрос больше 32 МБ | Лимит API | Не отправляет запрос, советует `/new`. |
| Диалог больше контекста модели (1M токенов) | Лимит модели | Сообщает и не сохраняет оборванный ход. |
| Весь `MAX_TOKENS` ушёл на размышления | Размышления расходуют тот же лимит | Сообщает и не сохраняет пустой ход. По умолчанию `MAX_TOKENS=64000`: столько рекомендует документация для потоковых запросов, максимум — 128000. |
| Сообщение пришло, пока генерируется прошлый ответ | Решение бота: один запрос на пользователя | Говорит, что сообщение не отправлено. |
| Telegram просит подождать (flood control) | Лимиты Telegram | Ждёт и повторяет. |

## 8. Безопасность

- **Секреты** — токен бота и ключ API — лежат только в `.env` на сервере. `.env` указан в `.gitignore` и `.dockerignore`, поэтому не попадает ни в git, ни в образ. Репозиторий публичный: никогда не коммитьте `.env`.
- **Доступ** по списку Telegram ID. Админов (`ADMIN_USER_IDS`) нужно указать явно. Раньше админами по умолчанию становились все из `ALLOWED_USER_IDS`, и любой допущенный пользователь мог раздавать доступ. Теперь это не так.
- **Контейнер** работает не от root (UID 10001), с файловой системой только для чтения (писать можно лишь в `/data` и `/tmp`), без capabilities и с запретом повышать привилегии. Память ограничена (`BOT_MEM_LIMIT`, по умолчанию 1 ГБ), чтобы бот не мог отнять её у VPN. Логи Docker ротируются: 3 файла по 10 МБ.
- **История диалогов** со всеми файлами, фото и PDF лежит в `data/bot.sqlite3` на сервере открытым текстом. Это приватные данные. Брошенные диалоги удаляются через `HISTORY_RETENTION_DAYS` дней (по умолчанию 30), текущий диалог хранится, пока пользователь не начнёт новый.
- **Что видит Anthropic:** всё, что отправлено боту, уходит в API (условия хранения данных — в политике Anthropic).
