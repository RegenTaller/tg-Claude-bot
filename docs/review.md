# Проверка кода, октябрь 2026

Что проверялось: работа с Claude API, работа с Telegram и aiogram, безопасность и контроль расходов, работа на сервере. Каждую находку я перепроверил по коду, по документации Anthropic, Telegram и Docker, по исходникам SDK `anthropic` 1.13.0 и aiogram 3.31. Находки про API дополнительно воспроизведены на исходном коде: поддельный SSE-поток подавался в настоящий SDK. Все исправления покрыты тестами в `tests/`.

## Claude API

| # | Находка | Вердикт | Что сделано |
|---|---|---|---|
| api-1 | Файлы в base64 копятся в истории; больше 32 МБ каждый запрос получает 413, а бот советует «попробовать ещё раз» | Подтверждено: лимит запроса 32 МБ, 20 МБ из Telegram дают ~27 МБ base64 | Перед отправкой оценивается размер запроса; при превышении бот советует `/new` и не шлёт обречённый запрос. Отдельный понятный текст для 413. Files API не внедрял: он хранит файлы у Anthropic до удаления, а лимит размера проблему уже закрывает |
| api-2 | Нет ограничения размера контекста: большие текстовые файлы навсегда в истории и дорожают с каждым сообщением | Подтверждено | Текстовые файлы — до 300 КБ. Предупреждение, когда диалог перевалил за 150 тыс. токенов (за 100 тыс. — для Haiku). Ход с `model_context_window_exceeded` не сохраняется, пользователю подсказка |
| api-3 | При fallback расход пишется под резервной моделью без цены ($0), отклонённая попытка не учитывается | Подтверждено воспроизведением | Учёт по каждой записи `usage.iterations`; добавлены цены резервных моделей; модели без цены показываются отдельно, а не как $0 |
| api-4 | Картинка файлом больше ~3.75 МБ отклоняется API | Подтверждено с поправкой: [для прямого API лимит 10 МБ base64](https://platform.claude.com/docs/en/build-with-claude/vision), 5 МБ — это Bedrock и Google Cloud | Pillow определяет формат по содержимому, уменьшает и сжимает |
| api-5 | `MAX_TOKENS=32000` мал для высокого effort: весь бюджет уходит на размышления, пустой ход сохраняется | Подтверждено воспроизведением и документацией (для потоковых запросов рекомендовано ~64K; у Haiku 5.5 на xhigh бывают пустые ответы) | По умолчанию 64000; ход без текста не сохраняется, пользователю объяснение |
| api-6 | Ошибка посреди стрима показывается как «ошибка 200», у 413/403/404 общий текст | Подтверждено по исходнику SDK и воспроизведением | Ошибки разбираются по классу и по `error.type`; показан уже полученный текст; в лог пишется `request_id` |
| api-7 | Смена модели или effort посреди диалога заново оплачивает всю историю | Факт подтверждён (кэш сбрасывается) | Сделано предупреждение, а не предложенное в заметках сообщение с effort внутри истории (beta). Причина: при серверном fallback тот же запрос уходит на Opus 4.8 или Sonnet 5, а эти модели такие сообщения не поддерживают. Риск сломать fallback я проверить не мог |
| api-8 | В `/usage` один множитель чтения кэша (0.1) для всех моделей; нет второй сетки Haiku | Подтверждено: Opus 5.5 — 0.05×, Fable 5.1 — 0.025×; у Haiku 5.5 промпт больше 100K в 5 раз дороже | Цены по моделям; стоимость считается на каждое обращение и хранится в базе |
| api-9 | Пустой текстовый блок посреди ответа сохраняется и ломает следующий запрос | Подтверждено воспроизведением; удалять такие блоки безопасно, проверка привязки размышлений их игнорирует | Пустые и пробельные текстовые блоки удаляются везде |

## Найдено дополнительно

| Все из `ALLOWED_USER_IDS` по умолчанию становились админами и могли раздавать доступ | Админы задаются только явно в `ADMIN_USER_IDS` |
| Не было лимита расходов на стороне бота | `USER_MONTHLY_LIMIT_USD` на каждого пользователя, кроме админов |
| Кнопка настроек под сообщением старше 48 часов роняла обработчик (сообщение недоступно для правки) | Проверка типа сообщения |
| Flood control Telegram при отправке длинного ответа приводил к потере ответа; во время стрима бот засыпал внутри чтения ответа | Повтор после ожидания; черновик во время стрима пропускает обновления, а не ждёт |
| Ошибка разметки HTML пересылала весь ответ заново (дубли), нарезка простого текста не учитывала UTF-16 | Переход на простой текст для отдельного куска; нарезка с учётом UTF-16 |
| Любая неожиданная ошибка оставляла «Claude думает…» навсегда | Общий перехват с сообщением пользователю и записью в лог |
| Обрыв соединения посреди ответа SDK выбрасывает как исключение `httpx2`, а не как свою ошибку: бот показывал бы «внутреннюю ошибку» и терял напечатанный текст (проверено) | Обрыв приводится к `APIConnectionError`; уже полученная часть ответа остаётся на экране |
| История с файлами в SQLite росла бесконечно | Брошенные диалоги удаляются через `HISTORY_RETENTION_DAYS` (по умолчанию 30 дней) |
| Контейнер работал от root, без ротации логов и без ограничения памяти — на одном сервере с VPN | Пользователь 10001, файловая система только для чтения, `cap_drop: ALL`, `no-new-privileges`, лимит памяти (по замеру пик ~420 МБ на PDF 20 МБ, по умолчанию 1 ГБ), логи 3 × 10 МБ |
| Скачивание файла из Telegram ограничено 30 секундами | 120 секунд |

## Что осталось оценкой

- `/usage` считает по ценам из `config.py`. Точная сумма — только в Anthropic Console: там учтены изменения цен и токены оборванных ответов.
- Утверждение, что прокси-VPN (Xray/3x-ui, Outline) не страдают от политики `FORWARD DROP` в Docker, — вывод из принципа их работы, а не из документации. Поэтому в инструкции есть обязательная проверка VPN после установки Docker и способ отката.
- Данные о Waicore (KVM, Ubuntu 24.04, локации) взяты из сторонних обзоров и бенчмарков: документация Waicore была недоступна.
